# Working on the literature database

- Start from the latest `origin/main`; inspect and preserve newer changes before editing.
- `index.html` is the live application. Files named `sport-env-lit-db-v*.html` and `index-old-*.html` are historical snapshots, not deployable replacements. Never copy a snapshot over `index.html` to deliver a feature.
- Keep features additive and isolated where practical. The follow workspace is in `follow-hub.js`/`.css`; local memos are in `memo.js`/`.css`.
- Preserve the `litdb-memo` IndexedDB database (version 1, `memos` and `files` stores) and existing personal storage keys. Never clear or reset user storage as a migration shortcut.
- Memo groups use a reserved `files` record keyed `memo-group-catalog`; notes reference stable `groupId` values. Preserve this metadata record and the optional `groups` array in v1 backups, including empty groups. Deleting a group must move all its notes (including archived/trash) to unfiled without deleting attachments. Preserve inline-image removal, keyboard selection and undo.
- Keep data refreshes separate from application source changes. Preserve current public access, full abstracts, multi-choice filters, all-result exports, independent following, local folders/notes, and lazy chart rendering.
- Before publishing, run `npm test`, inspect the diff, and bump the shell cache in `sw.js` when changing shell assets. Every new external application asset must be included in the service worker shell list.
- The regression workflow reports failures; it does not itself block GitHub Pages deployment. Do not describe it as a deployment gate unless repository deployment settings actually enforce it.

- The memo and following assets use versioned URLs to avoid mixing a new page with older cached modules. When changing these assets, keep their URL revisions in `index.html` and `sw.js` consistent, and update the full-page test inlining references.

- Figure study lives in `figure-hub.js` / `.css` and `figure-extract.js`. Preserve whole figures; never split A/B/C panels. Keep the vendored PDF.js worker, decoders and licenses together and lazy-load them; never add the 7 MB PDF runtime to the initial shell cache list.

- Figure study uses `litdb-figures` version 2 (`papers`, `figures`, `folders`). Upgrade additively; preserve PDF/image blobs, notes and manual paper titles. Figure backups v2 include folders and must still import v1 backups. Removing a folder moves its papers to unfiled without deleting their contents.

- Homepage research rings live independently in `paradigm-rings.js` / `.css`. Preserve the supplied 12 / 9 / 14 / 6 concepts plus 4 time scales, independent selections, slide-up dismissal and a reopen control. Auto-open only on homepage routes, never interrupt deep links to personal workspaces; do not couple the sheet to corpus loading or add a network/API dependency.

- Research prompts and primary method sources are in `paradigm-guide.js`; keep their editorial attribution (not a validated taxonomy or efficacy claim). The rings theme follows the main `data-theme` setting. Preserve the local Thinker asset, contextual links and independent selections when restyling.

- On-demand full text lives in `fulltext-reader.js` / `.css`. Query OpenAlex and load the shared PDF.js runtime only after an explicit read action. Keep per-user API keys out of Git, corpus records, backups, publisher URLs and service worker caches. OpenAlex content downloads need the user's key; preserve public-PDF/local-upload fallbacks, explicit failure states, current-page reading, cancellation, and PDF/canvas cleanup on close. Never bulk-download PDFs during startup.

- Structured reading uses `article-reader.js` / `.css`: Europe PMC exact DOI/PMID lookup and OA JATS XML are fetched only on explicit full-text actions, before PDF fallbacks. Never treat an abstract-only response as full text or render source HTML/attributes directly. Preserve headings, tables, figure captions, source/license attribution, and safe image URLs supplied by JATS. W opens full text only from a visible reader; typing in forms/contenteditable must never trigger it. Structured articles and PDF resources are released on close; personal notes and existing external source links remain intact.

- Meta opportunity scoping lives in `meta-hub.js` / `.css`, with shared candidate logic in `meta-core.js`. `meta-topics.json` is a reproducible corpus snapshot generated by `scripts/build-meta-candidates.cjs` from SHA256-verified shards; rules and editorial PICO drafts are in `meta-rules.json`. Load candidate data only when the workspace opens; never pre-cache it or run corpus matching/PDF/AI requests at startup. Explicit current-corpus rescans run in small batches and cancel on close. Preserve `litdb-meta-tracker` in the account-isolated personal backup. Candidate records, review signals, manually eligible reports, and independent studies must remain distinct; never infer novel/feasible Meta topics, study independence, or review search cutoff dates from counts or publication years alone.

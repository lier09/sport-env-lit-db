# 摘要与单位字段生成规范

`daily_update.py` 的 `split_shards()` 应保存完整 abstract，不得使用 `[:500]`。
移除巨大 `_authorships` 前，把其中 institutions[].display_name 提取到精简 `affiliations` 字符串数组。
前端已支持此字段，同时兼容包含原始 `_authorships` 的数据。

用户提供的脚本已在本机修改，修正版单独交付。
线上单位数据仍需要持有最新 merged.json 和 Supabase 上传环境的一方重新生成分片。
此次前端部署不改写主库数据，也不声称已补齐单位字段。


## 版本化发布

修正版会为四个分片生成 SHA-256、字节数、文献数和唯一版本号。
先上传 `versions/<version>/papers-1.json` 至 `papers-4.json`，四片全部成功后才上传 `manifest.json` 切换当前版本。
前端支持该清单并验证内容；无清单的现有库继续读取旧四片，按 ETag 校验本机缓存。
旧版网页应刷新后使用新清单；不再以逐个覆盖固定路径的方式发布新数据。
此机制需要持有完整数据和上传脚本的环境采用修正版 daily_update.py；本次 GitHub 部署只上线前端支持。

## 个人资料

个人收藏、文件夹、标签、笔记、已读及隐藏记录按当前账号保存在浏览器。
第一次迁移将旧浏览器资料保留给第一个迁移账号，原始旧键保留作备份；其他账号不会自动继承。
备份按钮导出个人资料，排除登录凭据、邀请码和 AI 配置。导入前验证字段，导入后刷新。
不实施跨设备云同步。浏览器清理仍会删除本机资料，请使用备份导出。

版本目录会保留旧数据；持有后台环境的一方应制定保留最近版本的规则，清理前备份，并保证不删除当前 manifest 使用的版本。
